Factory Inventory Management System

A demo full-stack inventory/orders dashboard: a Vue 3 single-page app talking to a single-file FastAPI backend that serves entirely in-memory data loaded from static JSON fixtures. There is no database and no write path — every route is read-only.

Vue 3 + Vite FastAPI In-memory JSON, no DB Read-only API

No UI kit, no CSS framework, no state-management library on either side — styling, i18n, and charts are all hand-rolled.

Data flow — a concrete trace

What actually happens when a user changes a filter on the Dashboard.

  1. User changes a <select> in FilterBar.vue, bound via v-model directly to the shared useFilters.js refs.

  2. Dashboard.vue holds a watch([selectedPeriod, selectedLocation, selectedCategory, selectedStatus], loadData) on those same singleton refs — no props or events are needed since every component shares one instance.

  3. loadData() calls getCurrentFilters() to build { warehouse, category, status, month }, then fires four requests in parallel with Promise.all: dashboard summary, orders, inventory, backlog.

  4. Each call goes through api.js, which serializes non-"all" filters into a query string and issues an axios GET to localhost:8001/api/*.

  5. The matching route in main.py runs apply_filters() / filter_by_month() over the in-memory lists that mock_data.py loaded from JSON at startup, then returns the result.

  6. FastAPI serializes the response (Pydantic-validated for typed routes, a plain dict for /dashboard/summary); axios resolves it back into Dashboard.vue's refs.

  7. Vue's reactivity re-runs dependent computed() properties (KPI cards, charts, tables), and the template re-renders — no manual DOM updates anywhere.

Known gaps & inconsistencies

Worth knowing before you build on top of this — none of these break the app today, but they're not what they look like at first glance.

Dead route

api.js calls /api/purchase-orders, but no such route exists in main.py and purchase_orders.json is an empty array — the Pydantic PurchaseOrder model is defined but unused.

Silent failure

api.js's four tasks methods hit /api/tasks*, which also doesn't exist. Calls are wrapped in try/catch, so the Tasks modal silently falls back to fully mocked state from useAuth.js instead.

Orphaned view

Backlog.vue is a complete standalone view duplicating logic already inlined in Dashboard.vue, but it is never registered as a route in main.js — unreachable from the UI.

i18n gap

Reports.vue uses hardcoded English strings instead of the useI18n.js t() function that every other view goes through.
